# База промптов

Промпт — главный актив проекта. Кадр можно переснять, набор референсов пересобрать, а формулировка,
которая после десяти заходов наконец дала верную застёжку, существует в одном экземпляре и
восстановлению не подлежит.

## Как устроено

```
prompts/
  РЕЕСТР.md                    что сработало: план → хвост SCENE → числа → файл
  ЭВОЛЮЦИЯ.md                  как метод дошёл до нынешнего вида, по датам
  ИСТОЧНИКИ.json               сырьё для ЭВОЛЮЦИИ: дата, изделие, длина, блоки, референсы, хвост
  <изделие>/                   всё по одной вещи
      base_*.txt               базы, от которых собираются серии
      <код>.txt                отдельные кадры: от базы отличаются двумя-тремя блоками
      материалы/               разобранные тексты наших прогонов с превью кадра
      эталоны/                 чужие промпты и образцы, от которых метод пошёл
      архив/<серия>/           тексты прежних серий, снятых до нынешних правил
  локации/                     кадры места без человека (ИНТЕРЬЕР)
  предметка/                   вещь на белом (ПЭКШОТ)
```

**Наше изделие одно** — `кардиган-шоколад-горошек`: 16 рабочих промптов, 19 в `архив/v3/`
и 25 разобранных в `материалы/`. Ещё четыре папки —
`мохер-серый-баска`, `поло-лимонное`, `куртка-стёганая`, `портрет-MIRA` — это шесть чужих
эталонов, и лежат они только в подпапках `эталоны/`. Ни одного нашего кадра по этим вещам не
снято. Путать их с нашей историей нельзя: из эталонов берутся приёмы, и каждый такой приём до
проверки на нашем изделии остаётся гипотезой.

Превью кадров лежат рядом с текстами уменьшенными до 1200 px — это не сдача, а опознавательный
знак: без картинки строка реестра читается вслепую.

**Новое изделие — новая папка.** Куртка, джинсы, платье получают собственную папку с собственной
базой и собственным архивом. Локации и предметка общие: место и пэкшот не привязаны к вещи.

## Как этим пользоваться

1. Открыть `РЕЕСТР.md`, найти строку с нужным планом. В колонке «последняя фраза SCENE» стоит
   приоритетная позиция — то, ради чего кадр вышел.
2. Взять файл промпта из той же строки за основу.
3. Поменять два-три блока: `CAMERA`, `SCENE`, при смене места `LOCATION`. Остальное не трогать —
   серия держится тем, что всё прочее побайтно совпадает.
4. `python3 tools/preflight.py <файл> --кредиты 0` → «РАЗРЕШЕНО ЗАПУСКАТЬ».

Писать промпт с нуля не нужно почти никогда. Если кажется, что нужно, — сначала проверить реестр.

## Правило, которое стоило нам тридцати восьми кадров

**Текст каждого отправленного кадра пишется в файл в момент отправки, а не после приёмки.**

Из принятых кадров текст сохранён меньше чем у трети: серии R, F и ST снимались правкой блоков
прямо в браузере — кадр принят, число записано, текст ушёл вместе с полем ввода. Точные числа
печатает `РЕЕСТР.md`, здесь они не дублируются. Среди потерянных — рекорд проекта по лицу.
Список пробелов печатается в конце `РЕЕСТР.md` и не будет оттуда убран, пока не закроется.

Кадр без сохранённого промпта считается неповторимым, каким бы удачным он ни вышел.

## Сборка реестра

```
python3 tools/registry.py            собрать РЕЕСТР.md
python3 tools/registry.py --проверка  показать пробелы, ничего не записывая
```

Запускается после каждого прогона, вместе с `deliver.py`. `РЕЕСТР.md` руками не правится: он
пересобирается целиком и правка потеряется.
