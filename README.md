# ai-studio-brand — рабочий комплект проекта

Публичный репозиторий. Здесь лежит всё, что нужно, чтобы начать съёмку с нуля в новой сессии:
инструменты, промпты и набор референсов. Готовых кадров здесь нет — они живут у заказчика на
диске и в архивах сдачи.

Документы проекта (ЗАКОНЫ, Состояние проекта, Журнал прогонов, Позы, Готовность) сюда **не
дублируются**: их единственный источник — Project в claude.ai, он подтягивается в каждый новый
чат сам. Два источника правил — это ровно та болезнь, которую мы лечили 17.08.

## Где что живёт

| | |
|---|---|
| GitHub | `github.com/chernookre-create/ai-studio-brand` — отсюда читает каждая новая сессия |
| Папка на маке | `~/Developer/AI-STUDIO/project/` — рабочая копия, сюда пишет Claude |
| Отправка | автоматическая, `launchd`-агент `com.aistudio.autosync` раз в 5 минут |
| Лог отправки | `/tmp/aistudio-autosync.log` |

Руками делать не нужно ничего. Изменения, которые Claude кладёт в папку, уезжают на GitHub сами;
следующая сессия клонирует уже новую версию.

Папка лежит в `~/Developer`, а не на Рабочем столе, намеренно: macOS не пускает фоновые задачи
к Desktop и агент падал с `Operation not permitted`.

## Запуск в новой сессии

    git clone --depth 1 https://github.com/chernookre-create/ai-studio-brand.git projects/brand
    pip install insightface onnxruntime rembg --break-system-packages

Проверка — одна команда:

    python3 tools/selftest.py

Ожидается **«ПРОШЛО — комплект исправен»**. Что она проверяет:

| пункт | что именно |
|---|---|
| первая строка | **число файлов в комплекте** — печатается, а не хранится в документах |
| 1 | одиннадцать скриптов на месте и синтаксически целы, включая сам `selftest.py` |
| 2 | шесть библиотек импортируются |
| 3 | девять слотов из `refs/CURRENT.json` существуют и не пусты; печатается серия |
| 4 | нет имён, различающихся только регистром (macOS схлопывает) |
| 5 | все рабочие промпты зелёные через `preflight` |
| 6 | каждый путь к `.md`/`.json`, упомянутый в коде, существует в комплекте — сверяется путь, а не имя файла |
| 6б | имена файлов съёмки не переехали из `CURRENT.json` в код |
| 6в | в базе промптов нет побайтных дублей (хеш содержимого) |
| 6г | у каждой записи `ИСТОЧНИКИ.json` есть поле `файл` и файл существует |
| 6д | `registry.py --проверка`: одинаковый код в двух сериях не связывается с чужим текстом |
| 6е | `00_readiness/state.json`: пункты совпадают со списком `readiness.py` (коды до двух разрядов), посторонних полей нет, «готово» и «нет» — списки, один пункт не стоит сразу в обоих |
| 7 | `--полный`: калибровка метрики лица на якоре, «сам к себе» ≈ 1.000 |

Каждый пункт с 6 по 6е появился после того, как реальный дефект прошёл мимо проверки. Проверку,
которая ни разу не падала, ломаем нарочно и убеждаемся, что она это заметила.

Если «УПАЛО» — комплект использовать нельзя, пока не починено. Код возврата ненулевой.

Запускать её надо **в контейнере сессии**, а не на маке: в рабочей копии на диске нет
`insightface` и `rembg`, и ставить их некуда — у папки на маке нет сети. На маке живёт хранилище,
проверки живут там, где съёмка.

## Что где

| папка | что внутри |
|---|---|
| `tools/` | одиннадцать скриптов проверки, сдачи и самопроверки |
| `prompts/` | база промптов: группы по изделиям, `РЕЕСТР.md` со счётом, `ЭВОЛЮЦИЯ.md` по датам, архив прежних серий |
| `results/` | вердикты и замеры прогонов — сырьё для реестра |
| `refs/` | набор референсов: девять слотов, якорь, паспорта изделий |

### tools/

| скрипт | что делает | когда |
|---|---|---|
| `check_prompt.py` | движок правил по классам кадра: ФОТО 20, ВИДЕО 8, ИНТЕРЬЕР 12, ПЭКШОТ 12. Блоки на месте, счётный признак с числом и запретом, хвост SCENE называет ломкий признак (`P1`) и не занят дефектом постобработки (`P2`) | до отправки |
| `preflight.py` | отчёт со строкой «РАЗРЕШЕНО ЗАПУСКАТЬ» | до отправки |
| `readiness.py` | процент готовности и список незакрытых признаков | до первого кадра серии |
| `face_id.py` | похожесть лица, ArcFace / buffalo_l. Норма ≥0.45, цель 0.60 | после кадра |
| `qc_frame.py` | масштаб узора через ширину лица, ±12% (калибровка ±3%). Кроп-кадры | после кадра |
| `scale_fig.py` | масштаб узора через рост фигуры (маска rembg), ±12%. Ростовые кадры — там `qc_frame` врёт до +8% при повороте головы | после кадра |
| `trim_border.py` | срезает чёрную кайму по краю файла; промптом не лечится | после кадра |
| `deliver.py` | папка на скачку: подписанные кадры, контактный лист, `ЗАМЕРЫ.csv`, `README.md` прогона, архив | после прогона |
| `selftest.py` | самопроверка всего комплекта одной командой | в начале сессии и после любой правки |
| `registry.py` | пересобирает `prompts/РЕЕСТР.md`: что сработало, на каком плане, с каким числом | после каждого прогона |
| `lineage.py` | пересобирает `prompts/ЭВОЛЮЦИЯ.md`: как метод менялся по датам, что в хвосте SCENE | после пополнения базы промптов |

Счёт пуговиц автоматом **не работает** — маска золотого путает горошины на свету с пуговицей
джинсов. Отрицательный результат, считается глазами.

### refs/ — набор текущей съёмки

**Какие девять файлов сейчас в слотах, описано в `refs/CURRENT.json`, а не в скриптах.**
`preflight.py` и `selftest.py` читают его; жёстко зашитых имён в коде нет, и `selftest` отдельным
пунктом проверяет, что они не появились.

Новая съёмка — правка одного файла:

```json
"серия": "look_v6 — студия, белая циклорама",
"слоты": { "5_локация": "refs/look_v6/UP_LOC.jpg", ... }
```

Скрипты не трогаются, промпты не трогаются. Ореховая стена лежит в слоте 5 **как значение на
сегодня**, а не как свойство метода: она отснята и работает, но к следующей съёмке в другом месте
отношения не имеет. Поле `ломкое_на_этой_локации` подсказывает, что ставить в последнюю строку
SCENE — на фактурной стене это её материал, на однородном фоне такой строки быть не должно вовсе.

Готовые варианты локации перечислены там же, в `готовые_варианты_локации`. Файлы `UP*.jpg` —
уменьшенные до 1200 px копии для загрузки в слоты; полноразмерные исходники лежат рядом.

### prompts/ — база промптов

Разложены по изделиям: `кардиган-шоколад-горошек/`, дальше `локации/` и `предметка/` — они общие.
Новое изделие получает свою папку. Подробно — `prompts/README.md`.

`prompts/ЭВОЛЮЦИЯ.md` — как метод дошёл до нынешнего вида: разобранные тексты по датам, с
колонкой «чьи тексты». Сколько их и сколько из них наших — печатает первая строка самого файла;
здесь число не дублируется. Собирается `tools/lineage.py` из `prompts/ИСТОЧНИКИ.json`, руками не
правится.

`prompts/РЕЕСТР.md` — таблица «что сработало»: план кадра, последняя фраза SCENE, похожесть лица,
отклонение узора и файл промпта. Собирается `tools/registry.py` из `results/*.json` и самих
промптов, руками не правится.

Внутри изделия: `base_*.txt` — базы серий, отдельные кадры отличаются от базы двумя-тремя блоками,
всё прочее побайтно совпадает. `архив/` — тексты серий, снятых до нынешних правил: реестр их
читает, `preflight` по ним не судит.

**У большинства принятых кадров текста промпта нет.** Серии R, F и ST снимались правкой блоков
прямо в браузере, текст не сохранялся, и воспроизвести эти кадры нельзя. Сколько именно — печатает
`РЕЕСТР.md`; здесь число не дублируется, оно меняется с каждой сборкой. Отсюда правило: промпт
пишется в файл в момент отправки, а не после приёмки.

### results/ — как устроены записи

| поле | что значит |
|---|---|
| ключ записи | **исходное имя файла из сервиса** — ни на что не влияет и в счёт не идёт |
| `код` | наш ярлык кадра; **связываем только по нему** |
| `вердикт` | `ок` / `брак` |
| `лицо`, `узор`, `счёт` | замеры и счёт глазами |
| `тип: кроп` | кадр не генерировался, а вырезан из принятого — в «сгенерировано» не идёт |

Имя файла и код разъехались по всей серии C: `C01.png` содержит кадр `F02`, `P01.png` — кадр
`ST01`, три разных кадра называются `P05*`. Это не дефект, а соглашение: имя — от сервиса, код —
наш.

`registry.py` берёт подпись серии из **префикса кода**, а не из имени файла результатов: в
`v4.json` две серии (S — юбка и обувь, R — круг 360), в `v5.json` — F и C. Поиск текста промпта
ограничен серией: архив v3 виден только кадрам v3, иначе `final:P05` получает текст архивного
`v3:P05` — чужой промпт под видом сохранённого.

**Величины «сколько кадров вышло с первого раза» в проекте нет**: поля в данных нет, а два
косвенных способа счёта дают разные ответы.

## Что сюда не кладём

Готовые кадры и PNG-оригиналы: несколько гигабайт, GitHub отклоняет файлы больше 100 МБ. Они
уходят через `deliver.py` в `05_deliver/<прогон>` рабочей директории и живут у заказчика.
Промежуточный брак: он не нужен никому, включая нас. Документы проекта: см. выше.

## preflight.py — что он блокирует, а что нет

Блокирует: отсутствие любого из девяти слотов набора, красную проверку промпта, неуказанную
стоимость. Не блокирует и не может проверить: прочитаны ли документы проекта — они живут в
Project claude.ai, на диск не кладутся, и ответственность за «прочитано глазами» на операторе.

Тип кадра **определяется по тексту промпта сам** — «this is an empty room» даёт интерьер,
«studio product photograph» пэкшот, «start frame» видео. Выбранный тип печатается третьей строкой
отчёта, так что видно, если он определился не так. Флаги `--интерьер`, `--пэкшот`, `--видео`
остались как ручное переопределение; если флаг расходится с текстом, отчёт об этом предупредит.

До 17.08 флаг был обязателен, и забытый флаг выглядел как настоящий брак: интерьерный промпт
получал девять нарушений про лицо, позу и пуговицы, которых в кадре нет вовсе (Ф62). Полагаться
на память человека в этом месте оказалось нельзя.

**Правка 17.08.2026.** Прежний preflight требовал семь документов по путям `00_RULES/`,
`04_poses/`, `00_readiness/` и печатал «ЗАПУСК ЗАПРЕЩЁН» на каждом кадре при исправном промпте.
Проверка, которая срабатывает всегда, не проверяет ничего — её перестают читать. Список заменён
на девять слотов, которые действительно лежат рядом.
